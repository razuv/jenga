# Jenga

3D Jenga на Three.js и Rapier. Физика в браузере, P2P-комнаты до 6 участников и локальная игра на 1–6 человек. В онлайн-партии создатель комнаты — хост. Деревянные текстуры генерируются локально. Игроки сидят вокруг стола с случайно назначенными мемами вместо лиц. Мемы одинаковы для всех участников комнаты и хранятся в public/memes.

## Запуск

Node.js 22.12+:

```
npm install
npm run dev
```

Откройте http://localhost:3000. Через «Пригласить друзей» выберите локальный или онлайн-режим. Создатель онлайн-комнаты копирует ссылку и после подключения игроков нажимает «Начать игру».

Выберите блок ниже двух верхних этажей, потяните его вдоль длинной стороны мышью или пальцем. Полностью извлечённый блок после отпускания автоматически переносится наверх; завершение хода обрабатывает физический движок. Незавершённое вытягивание можно продолжить повторным захватом блока или отменить выбором другого; застрявший захват автоматически освобождается через 6 секунд. С клавиатуры: стрелки выбирают блок, Enter берёт его, влево/вправо вытягивают, Enter отпускает, Escape отменяет. Камера вращается перетаскиванием пустого пространства, масштаб — колесом / жестом двумя пальцами.

## Онлайн без выделенного игрового сервера

1. Выберите «Пригласить друзей → Онлайн» и введите имя.
2. Оставьте код пустым и нажмите «Играть» — ваш браузер станет хостом.
3. Скопируйте ссылку кнопкой с кодом комнаты и отправьте друзьям. Код содержит 8 символов.
4. Дождитесь игроков и нажмите «Начать игру». Всего доступно 6 мест, включая хоста.

Хост считает физику Rapier и проверяет право хода. Гости передают действия через WebRTC и получают положение блоков 20 раз в секунду. Мем-аватары и список игроков синхронизируются хостом. Если гость выходит, партия продолжается; если выходит хост — завершается у всех. Переноса хоста и восстановления партии после перезагрузки страницы нет.

Для первоначального подключения используется публичный PeerJS Cloud. Используются публичные STUN/TURN PeerJS с дополнительным TCP-вариантом; собственного аккаунта и игрового сервера не требуется. В отдельных сетях прямое соединение невозможно и требуется доступный TURN-ретранслятор. Доступность публичной инфраструктуры не гарантируется. Держите вкладку хоста открытой и активной: браузеры могут замедлять фоновые вкладки. Камера и микрофон не запрашиваются.

Если соединение останавливается на ICE, можно подключить управляемый TURN без собственного игрового сервера: задайте `VITE_ICE_SERVERS` JSON-массивом ICE-серверов (пример в `.env.example`). Для GitHub Pages добавьте одноимённую переменную репозитория **Actions → Variables** и повторите сборку. Для сетей с блокировкой UDP обычно нужен адрес `turns:...:443?transport=tcp`. Настройка входит в публичный JavaScript, поэтому используйте ограниченные/временные TURN-доступы, а не секретный API-ключ сервиса.

Документация: https://peerjs.com/client/faq

## Необязательный Node.js-сервер (прежний режим)

```
npm run build
NODE_ENV=production PORT=3000 node server.js
```

Этот альтернативный режим включается только при заданном `VITE_SERVER_URL` во время сборки. Для него нужен постоянный Node.js-сервер с поддержкой WebSocket. По умолчанию используется P2P. HTTPS настраивается на хостинге или reverse proxy. Все участники должны открывать один адрес сервера; localhost доступен только с того же компьютера. В домашней сети используйте LAN-адрес компьютера.

`npm test` проверяет устойчивость, ограничения выбора и перенос блоков. Комнаты хранятся в памяти; перезапуск сервера завершает партии. При отключении участник покидает комнату, ход переходит оставшимся. Физика приближённая; вытягивание ограничено продольной осью блока.

## GitHub Pages

Локальная игра работает целиком в браузере, включая физику Rapier и до 6 игроков. Node.js на Pages не нужен. Онлайн-комнаты по умолчанию работают через P2P: хостом становится создатель комнаты.

1. В репозитории откройте **Settings → Pages → Source → GitHub Actions**.
2. Отправьте изменения в `main` или запустите **Actions → Deploy GitHub Pages → Run workflow**.
3. После успешного workflow игра будет доступна на `https://razuv.github.io/jenga/`.

Workflow устанавливает зависимости, запускает тесты, собирает сайт с базовым путём Pages и публикует только `dist`. Изображения, ссылки и приглашения учитывают путь `/jenga/`.

Проверка той же статической сборки локально:

```
npm ci
npm test
npm run build:pages
npm run preview:pages
```

Откройте `http://127.0.0.1:4173/jenga/`. В этой сборке локальная партия не обращается к Socket.IO.

Для P2P-комнат переменные GitHub Actions, отдельный сервер и API-ключи не нужны. Workflow Pages собирает P2P-версию. Ссылка приглашения сохраняет путь `/jenga/`.

Если нужен прежний серверный режим, соберите клиент вручную с `VITE_SERVER_URL=https://your-server.example.com`, а сервер запустите с `NODE_ENV=production` и `CLIENT_ORIGIN=https://razuv.github.io`. Не добавляйте секретные ключи в переменные `VITE_*`: они входят в публичную сборку.

`npm test` проверяет локальную физику, ограничения ходов, комнаты Socket.IO и P2P-протокол с моделируемыми соединениями: 6 участников, переполнение, гостевые действия вне хода, отключение гостя и завершение при уходе хоста. При проверке в браузерах регистрация комнаты и сигнализация прошли, но реальное ICE-соединение в текущей сети завершилось ошибкой. Успешная передача игровых данных между разными сетями пока не подтверждена; тестовая модель не воспроизводит NAT и блокировки провайдера.
